# RCA — Request to add `co.hireavatar.app://auth/callback` to managed Clerk production config

## Request
Add custom-scheme redirect `co.hireavatar.app://auth/callback` to the Emergent-managed Clerk **production** instance for https://www.hireavatar.co, and confirm (a) whether the managed config can add it and (b) whether it is compatible with the current web-only React app. (No deploy / no secret changes requested.)

## What I verified (active run b1596db6-2677-4864-95f9-622c11a098fe, source in eph sandbox)
- **App is web-only React.** `frontend/package.json` uses `@clerk/react@6.17.0` (browser SDK), `react-dom@19`, `react-router-dom@7`, `react-scripts`/craco. There is **no** `@clerk/clerk-expo`, `@clerk/clerk-react-native`, React Native, Expo, or Capacitor dependency — nothing that registers or consumes a `*://` custom URL scheme.
- **All Clerk redirects are https/path-based.** `src/components/auth/ClerkAuthProvider.jsx` sets `signInUrl="/sign-in"`, `signUpUrl="/sign-up"`, `signInFallbackRedirectUrl="/app"`, `signUpFallbackRedirectUrl="/app"`, `afterSignOutUrl="/"`, and routing via react-router `navigate()`. No custom-scheme handling anywhere.
- **Clerk runs through the app's own-domain proxy.** `backend/clerk_auth.py`: `PROXY_PATH = "/api/__clerk"`, production-only (`pk_live_`), relaying Clerk Frontend API. Frontend reads `proxy_url` from `/api/clerk/config`. This matches the prior RCA's proxy `https://www.hireavatar.co/api/__clerk`.
- **Domain/binding state is consistent with the prior RCA.** `describe_deployment_state`: `deployed_url = https://brandface.emergent.host` (default), custom domains `www.hireavatar.co` and `hireavatar.co` both `verified:true`. The Clerk production instance still being bound to `brandface.emergent.host` (per prior RCA) is unchanged and is a separate, platform-side rebind item.

## Answers
1. **Can the managed config add the custom-scheme redirect?** Only the Emergent/Clerk-managed side can — I have **no tool** to view or edit the Clerk dashboard (allowed redirect/origin list, custom-domain binding). Clerk *does* permit non-https custom schemes in its redirect allowlist, but exclusively for **native (iOS/Android/Expo) OAuth deep-link** flows. So it is technically addable, but by Platform, not by me.
2. **Is it compatible with the current web-only app?** **No / inert.** A browser cannot complete an OAuth callback on a `co.hireavatar.app://` scheme — that targets an installed native app. The deployed React app uses only https path redirects through `/api/__clerk`. Adding this entry would not be used by, and would not affect, the current web app. It only becomes meaningful once a native mobile client (e.g. Expo/iOS/Android using a native Clerk SDK) exists.

## Conclusion
The custom-scheme redirect is a **native-app** artifact. It is safe but useless for today's web-only deployment, and adding it must be done Platform-side on the managed Clerk production instance. The pending `brandface.emergent.host → www.hireavatar.co / hireavatar.co` custom-domain rebind + `/api/__clerk` proxy (prior RCA) is an independent Platform item and is not advanced or blocked by this request.
